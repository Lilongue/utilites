# План сессий по требованиям

> Одна сессия = одна тема. Цель — список user stories и согласованный план
> реализации, а не код. Контекст задачи — в [CONTEXT.md](CONTEXT.md).
> Итоги раунда 0 (боли и границы) — в [round-00-pains-and-scope.md](round-00-pains-and-scope.md).

## Как проводить сессию

1. В новой сессии попросить прочитать `CONTEXT.md` и блок нужной сессии отсюда.
2. Обсудить вопросы сессии; записывать решения, а не только мнения.
3. Результат сохранить в `docs/requirements/round-NN-<тема>.md`.
4. Обновить таблицу статусов ниже и, если появились новые факты, — `CONTEXT.md`.

Готовый промпт для новой сессии:

> Прочитай `docs/requirements/CONTEXT.md` и `docs/requirements/SESSIONS.md`.
> Проведём сессию N: <тема>. Задавай вопросы по одному, фиксируй ответы,
> в конце запиши результат в `docs/requirements/round-NN-<тема>.md`.
> Код не пиши — только требования.

## Детали сессий

### Сессия 0 — Словарь: книга, файл, приложение

Вопросы: что считается одной книгой, когда файлов много (комикс-серия, многотомник);
чем файл отличается от книги; что такое приложение к книге (диск с кодом) и как оно
не должно мешать; как в модели живёт бумажный экземпляр без файла; нужна ли серия
как отдельный уровень.
Выход: согласованный словарь понятий + решение, какие сущности есть в модели.

### Сессия 1 — Поиск: «где лежит книга»

Вопросы: последний реальный случай поиска; что вводится (название/автор/тема,
рус/лат); что значит «нашёл» (путь, открыть файл, открыть папку); как выдача
показывает книгу с несколькими файлами и бумажный экземпляр.
Боли: P1, P2, P4.
Выход: 3–5 user stories вида «Как читатель, я хочу …, чтобы …» + список критериев
приёмки для каждой.

### Сессия 2 — Пополнение и актуальность каталога

Вопросы: как новые книги попадают в уже существующий каталог (и что значит
«в текущую структуру» — папки на диске или записи каталога); что происходит при
повторном прогоне по той же папке; как помечаются пропавшие файлы; что делать
при переезде папок и переименовании; как отличить «многофайловую книгу» от дубля.
Боли: P6, P10, P11.
Выход: сценарии пополнения + user stories + правила «что считается пропавшим».

### Сессия 3 — Заметки и связь с книгой

Вопросы: когда возникает заметка (во время чтения на ПК, на бумаге, после);
что это (цитата, мысль, оценка, конспект главы); к чему привязана (книга/страница/
глава); как ищется — отдельно по книге и по свободному тексту; что с ней делают
дальше (экспорт, перечитывание); где хранить.
Боли: P5.
Выход: модель заметки + сценарии + user stories.

### Сессия 4 — Данные, хранение, миграция

Вопросы: где живёт база; что важнее — портативность или скорость; нужен ли
бэкап/экспорт; что делать со старым `library.log` и `dbutils`; нужен ли доступ
с других устройств.
Выход: решения по хранению + план миграции.

### Сессия 5 — Интерфейс и запуск

Вопросы: CLI, локальная веб-страница, GUI, горячая клавиша; сколько раз в день
пользуешься; нужен ли запуск с телефона; важна ли скорость ввода.
Выход: выбор формы интерфейса и границы MVP.

### Сессия 6 — Свод user stories и приоритеты

Свести US из сессий 0–5, убрать дубли, расставить приоритеты (must/should/could),
выделить MVP.
Выход: `docs/requirements/USER-STORIES.md`.

### Сессия 7 — План реализации

Разбить MVP на вертикальные шаги (каждый — коммит с тестами), определить
критерии готовности и порядок работ.
Выход: `docs/requirements/IMPLEMENTATION-PLAN.md`.
