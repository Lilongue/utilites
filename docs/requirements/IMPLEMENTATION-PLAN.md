# План реализации — этап 1 «Каталог и поиск», 25.11.2026

> Основание: [USER-STORIES.md](USER-STORIES.md) (US-1…5, 9, 10, 17, 19, 21) и решения
> раундов 0–5. Код не писался.
> Соглашения репозитория: `master` не трогаем, работаем в ветке, коммиты — после «ок»,
> шаг = один коммит = зелёные тесты + diff на просмотр.

## Вводные

- Масштаб: **десятки тысяч** позиций в одном корне на одном диске.
- Структура каталога осмысленная: каждый уровень пути — тег (тема / подтема / автор / серия).
- На старте **пересборка каталога допустима**: структуру владелец меняет руками и пересобирает,
  тонкий дифф не нужен. Поэтому в этапе 1 — полная перестройка, инкремент откладывается.
- База: SQLite, один файл `\.booklibrary\library.db` внутри корня библиотеки. Пути — относительно корня.
- Интерфейс: консоль (REPL), без GUI и веба.
- Старый код (`collector.py`, `runner.py`, `dbutils/`) **не удаляем** без отдельного согласования.

## Соглашения о шагах

1. Новый код — в новом пакете, старый не переписываем на ходу.
2. Каждый шаг заканчивается рабочим `bl`-ом и тестами. Промежуточных «полушагов» нет.
3. Тесты — `pytest` на временных каталогах; реальная библиотека в тестах не участвует.
4. Один шаг = один коммит в рабочей ветке.
5. Каждый шаг проверяется на **реальной** библиотеке вручную: «работает» решает владелец.

**Правило:** шаг не начинается, пока не приняты решения, привязанные к нему в карте ниже.

## Шаги

### Шаг 0. Согласования перед кодом

Решаем: имя пакета/команды, ветка, корень библиотеки, судьба старых артефактов.
Готово, когда: есть ветка и известно, где реальные данные для ручных проверок.

### Шаг 1. Каркас: пакет, база, бэкап

Что делаем: пакет, точка входа `bl`, конфиг корня, SQLite-схема v1 (`books`, `files`,
`meta.schema_version`), индексы по имени/автору/пути, автокопия базы перед записью.
Команда `bl status`: корень, путь базы, число книг.

Нужны решения: конфиг (где и в каком виде), политика хранения копий.

Проверка: тест на создание базы, версию схемы, появление копии при записи.

Готово, когда: `bl status` на пустой папке показывает 0 книг и говорит, где лежит база.

### Шаг 2. Полная перестройка каталога

Что делаем: обход корня, книжные расширения, пути **относительно корня**, идемпотентность,
команда `bl rebuild`.

Нужны решения: список расширений, архивы, регистр/русские имена, целевое время пересборки.

Проверка: тест на временном дереве, повторный запуск, замер на реальных данных.

Готово, когда: число книг соответствует диску, пути относительны, повторный rebuild не плодит
дубли, время укладывается в согласованный ориентир.

### Шаг 3. Книга-папка

Что делаем: эвристика «папка без книжных файлов внутри — кандидат в одну книгу», подтверждение
в консоли, сохранение решения в базе.

Нужны решения: правила эвристики; поведение при изменении содержимого подтверждённой папки.

Проверка: папка с 12 картинками = 1 книга; папка с 18 PDF = 18 книг; подтверждение не спрашивается
повторно.

Готово, когда: комикс-папка в каталоге — одна строка.

### Шаг 4. Поиск

Что делаем: поиск по части названия и автора, регистронезависимо, с лимитом; команда `bl find`.
Строка результата: название, автор, раздел. Пустой результат — явное «не найдено».

Нужны решения: ранжирование, лимит, нечёткость.

Проверка: фрагмент слова, регистр, пустой результат.

Готово, когда: US-2, US-3, US-5 выполняются на реальной библиотеке.

### Шаг 5. Открыть файл и папку

Что делаем: `bl open <id> file|folder`; книга-папка — открывается папка; книга без файла —
понятное сообщение.

Нужны решения: способ открытия на Windows, поведение для бумажной книги.

Проверка: тест с подставным «открывателем» (без окон в тестах).

Готово, когда: US-4 выполняется для обоих типов книг.

### Шаг 6. Разделы

Что делаем: `bl ls <путь>` — подразделы и книги текущего уровня.

Нужны решения: только листание или ещё фильтр по уровню пути.

Проверка: тест на дереве из шага 2.

Готово, когда: US-1 выполняется.

### Шаг 7. Целостность и стартовая проверка

Что делаем: `bl check` — пропавшие помечаются «нет на диске», новые добавляются; автозапуск
при старте в согласованном режиме.

Нужны решения: режим автозапуска (всегда / флаг / фон), быстрота проверки на десятках тысяч.

Проверка: удалить файл, добавить файл, проверить сохранность ручных данных.

Готово, когда: US-9 и US-21 выполняются, старт не превращается в ожидание.

### Шаг 8. Бэкап и откат

Что делаем: `bl backup list|restore`, политика хранения копий.

Нужны решения: сколько копий и где.

Проверка: изменение → откат → данные вернулись.

Готово, когда: US-17 выполняется без ручного копирования.

### Шаг 9. REPL

Что делаем: интерактивная оболочка: команды, `help`, поведение пустого ввода, выход.
Сервисы шагов 1–8 переиспользуются.

Нужны решения: набор команд, поведение пустого ввода.

Проверка: тест сценария «ввод → вывод» через подставной ввод/вывод.

Готово, когда: US-19 выполняется целиком: запустил, нашёл, открыл, вышел.

## Критерии готовности этапа 1

- Пересборка на десятках тысяч позиций укладывается в согласованный ориентир.
- Поиск отвечает быстро на глаз.
- Пропавшие файлы помечены, но не удалены.
- База переживает сбой: есть копия и откат.
- Ни одна операция не требует ручного редактирования базы.

## Не входит в этап 1

- Папка «входящие» и авторазбор в фоне (этап 2).
- Заметки: модель, привязка, мнение, перенос из Excel/телефона (этап 3).
- Поиск заметок (won't).
- GUI и веб.
- Инкрементальный скан — только полная пересборка + проверка целостности.
- Изменение древовидной структуры средствами утилиты.

## Риски

1. **Эвристика «папка = книга»** на десятках тысяч позиций: ложные срабатывания и скорость.
2. **Длинные пути Windows** (260 символов) на глубокой структуре.
3. **Раздел как папка и как тег** — в этапе 1 раздел только папка.
4. **Соблазн переписать старый код** — старые модули остаются как есть.
