# Сессия 1 — Поиск: «где лежит книга», 20.11.2026

> Результат: user stories + критерии приёмки. Код не писался.
> Боли: P1 (найти файл), P2 (есть ли книга), P4 (искать по смыслу).

## Что выяснили

- Каталог на диске **уже структурирован**: `\Library\IT\python` и т.п. Место для новой
  книги владелец выбирает вручную. Значит структура разделов — не побочный эффект, а
  часть модели данных.
- Два **разных** поисковых режима, их нельзя смешивать в один:
  1. **«Что почитать»** — навигация по разделам и темам. Структура важна, текст — почти нет.
  2. **«Что прочитал / где эта книга»** — вспоминание по части названия, ключевым словам,
     тексту своих заметок. Структура не помогает.
- Поиск по названию/словам — **по всему каталогу сразу**, текущий раздел роли не играет.
- «Нашёл» = могу **открыть файл** и **открыть папку**. Оба действия нужны.
- Строка результата: название, путь/раздел, автор, мои заметки (если есть).
  Формат, размер и дату показывать не нужно.
- Заметки участвуют в поиске как текст. Значит в сессии 3 заметки — не «отдельный экран»,
  а источник поискового индекса.

## User stories (черновик)

### US-1. Листать каталог по разделам

Как читатель, я хочу открыть нужный раздел каталога (Library → IT → python) и увидеть
книги в нём, чтобы выбрать, что почитать, не вспоминая имён файлов.

- Критерии приёмки:
  - Показано дерево разделов, соответствующее структуре папок на диске.
  - В разделе видны **книги**, а не файлы; книга-папка — одна строка, а не 12.
  - Переход между разделами не требует пересборки каталога.

### US-2. Найти по части названия, автору или слову из заметки

Как читатель, я хочу ввести часть названия, фамилию автора или слово из своей заметки и
получить все подходящие книги из всего каталога, чтобы найти то, что уже прочитал.

- Критерии приёмки:
  - Поиск идёт по всему каталогу, без ограничения текущим разделом.
  - Совпадение частичное (введён кусок слова — книга найдена).
  - Ищет по названию, автору и тексту заметок.
  - Поиск по заметкам работает, даже если название книги не совпало.

### US-3. Понять, что это та книга

Как читатель, я хочу видеть в результате название, автора, раздел и свою заметку, чтобы
отличить нужную книгу от одноимённой и вспомнить, зачем она мне.

- Критерии приёмки:
  - В строке результата: название, автор, путь/раздел, фрагмент заметки.
  - Если заметки нет — поле пустое, а не «нет данных».
  - Если в книге много файлов, строка одна (книга, а не файл).

### US-4. Открыть книгу или её папку из результата

Как читатель, я хочу из найденной книги открыть файл или папку, чтобы не искать её
заново в проводнике.

- Критерии приёмки:
  - Для книги-файла: открывается этот файл.
  - Для книги-папки: открывается папка.
  - Для бумажной книги: открытие недоступно, но книга находится и видна.

### US-5. Отличать «нет в каталоге» от «не искал»

Как читатель, я хочу явный ответ «не найдено», чтобы не качать книгу заново и не думать,
что я плохо искал.

- Критерии приёмки:
  - Пустой результат — это явное сообщение «не найдено», а не пустой экран.
  - Сообщение говорит, что книги нет **в каталоге**, а не что её нет на диске.
  - Чтобы это было правдой, охват сканирования должен быть известен (требование к сессии 2).

## Решения

1. Поиск делится на два режима: навигация по разделам и текстовый поиск. Это два разных
   требования, а не один экран с фильтрами.
2. Структура разделов берётся из папок на диске; отдельного «справочника категорий» нет.
3. Текстовый поиск — глобальный.
4. «Нашёл» подразумевает два действия: открыть файл и открыть папку.
5. В результате не показываем формат, размер и дату.

## Открытые вопросы

1. Что значит «открыть» для бумажной книги, у которой нет файла? Показывать «на полке»?
2. Нужен ли нечёткий поиск: опечатки, другая раскладка (рус/лат)? P3 из охвата выведен,
   но «часть названия» может быть введена латиницей.
3. Ранжирование: что выше при равном совпадении — название или текст заметки?
4. Сколько текста заметки показывать в строке результата?
5. Насколько быстрым должен быть поиск (мгновенно по мере ввода?) — вопрос к сессии 5.
