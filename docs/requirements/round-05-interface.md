# Сессия 5 — Интерфейс и запуск, 25.11.2026

> Результат: выбор формы интерфейса и границы MVP. Код не писался.

## Что выяснили

- Использование **в двух режимах**: частый короткий поиск и редкие длинные сессии
  (разбор кипы, заметки). Интерфейс должен обслуживать оба, но в MVP — по-разному.
- **MVP — консоль.** GUI и веб — следующая ступень, не сейчас.
- Приоритет внутри консоли: **удобное добавление новых книг**. «Если сделаем удобное добавление
  в консоли — уже супер».
- Форма работы — **REPL + автоматизации**, а не только подкоманды:
  - часть вещей делается **при старте** (проверка целостности и т.п.);
  - авторазбор из папок (входящие, отчёты) идёт **в фоне** и не блокирует командную строку;
  - незавершённый фоновый разбор **продолжается при следующем старте** — закрыть консоль не страшно.
- **Поиск заметок в MVP не делаем.** Владелец: «поиск заметок сейчас удобнее в базе напрямую
  искать, а не в нашем приложении, поэтому с этим не заморачиваемся». Это снимает US-12 из MVP.

## Решения

1. **Интерфейс MVP — REPL в консоли** с командами и автодополнением поведения.
2. **Старт утилиты делает проверки**: целостность каталога, догон незавершённого разбора.
3. **Авторазбор — фоновый**, из настроенного списка папок. Приглашение REPL доступно всё время.
4. **Очередь фоновых задач устойчива к выходу**: недоделанное продолжается при следующем старте.
5. **GUI и веб — после MVP**, но слой данных к ним не привязан (решение сессии 4, п. 5).
6. **Поиск заметок — вне MVP.** Заметки доступны прямыми запросами к базе.
7. **Удобство добавления важнее полноты команд**: лучше меньше команд, но добавление доводится
   до конца без ручного шаманства.

## User stories (черновик)

### US-19. Найти книгу из консоли

Как читатель, я хочу запустить утилиту и сразу найти книгу, чтобы не открывать проводник и не
вспоминать, в какой папке что лежит.

- Критерии приёмки:
  - Запуск — одна команда; открывается приглашение REPL.
  - Ввод части названия/автора даёт список результатов (US-2) сразу.
  - Из результата можно открыть файл и папку, не выходя из REPL (US-4).
  - Подсказка по командам доступна из REPL.

### US-20. Авторазбор не мешает работе

Как читатель, я хочу, чтобы новые книги разбирались в фоне, а не заставляли ждать, пока
закончится скан.

- Критерии приёмки:
  - Авторазбор из папок запускается сам и не блокирует приглашение.
  - Видно, что разбор идёт и сколько осталось.
  - При выходе незавершённые задачи сохраняются и продолжаются при следующем старте.
  - Результат разбора появляется в каталоге без отдельного запуска скана.

### US-21. Старт утилиты сам проверяет целостность

Как читатель, я хочу при запуске узнавать, всё ли в порядке с каталогом, чтобы не держать это
в голове.

- Критерии приёмки:
  - При старте выполняется проверка целостности (US-9): пропавшие файлы, новые файлы.
  - Результат виден коротким сообщением: что изменилось.
  - Проверка не превращает запуск в ожидание (или идёт в фоне с индикатором).
