# Раунд 0 — Боль и границы

> Дата: 20.11.2026. Состояние: черновик; границы ждут подтверждения.
> Основание: разбор старого кода и логов в репозитории + ответы владельца в чате.

## Зачем этот раунд

Обсуждение началось с «сформулируем требования». Прежде чем идти по сессиям,
зафиксировано, какую боль утилита должна снимать: иначе вопросы сессий бьют мимо.

## Подтверждённые боли

| № | Боль (словами владельца) | Что должно стать правдой |
|---|--------------------------|---------------------------|
| P1 | Не могу быстро найти файл книги | По памяти о книге получаю путь и открываю файл за секунды |
| P2 | Не знаю, есть ли книга вообще | Каталог полный и актуальный: «нет в каталоге» = «нет у меня» для просканированных мест |
| P4 | Ищу по смыслу, а имена файлов — мусор | Поиск по автору/названию/темам, а не по имени файла |
| P5 | Теряются заметки и цитаты | Заметка привязана к книге; поиск по книге и по свободному тексту |
| P6 | Каталог невозможно поддерживать | Новые книги добавляются без пересборки, пропавшие помечаются, повторный прогон безопасен |
| P9 | Бумажные книги тоже надо учитывать | Книга без файла существует и находится |

## Добавлено владельцем в свободной форме

| № | Формулировка | Следствие |
|---|--------------|-----------|
| P10 | «Как добавить новые книги в текущую структуру» | Главный сценарий пополнения: каталог уже есть, появились новые файлы — как влить их, не ломая прежнее. **Требует уточнения:** «структура» — это папки на диске или записи каталога |
| P11 | Одна книга — много файлов (комиксы) | Нужна модель «книга → файлы», а не «книга = файл». Связано с P2: 12 файлов не должны выглядеть как 12 книг |
| P12 | У книги бывают приложения (диск с кодом) | Решено в сессии 0: приложение — не отдельная сущность, а содержимое книги-папки |
| P13 | Многофайловую книгу (комикс, html-книга) приходится вручную упаковывать в архив | Книга-папка без упаковки; архив как способ хранения больше не нужен |

## Границы (черновик — требует подтверждения)

**В охвате:** каталог книг на локальном ПК, файлы на дисках, бумажные экземпляры,
заметки и цитаты, поиск по всему этому.

**Вне охвата (предлагается):** чтение книги внутри утилиты, скачивание из сети,
синхронизация между устройствами, OCR и распознавание текста из PDF, конвертация
форматов, мобильный клиент.

4. Заметка — свободный текст или структура (цитата / страница / глава)?

## Словарь (сессия 0, 20.11.2026)

| Понятие | Решение |
|---------|---------|
| **Книга** | Единица, которую человек ищет: название + автор, если известен. Может иметь 0..N файлов. Наличие файлов не обязательно |
| **Файл** | Конкретный файл на диске: pdf, fb2, djvu, docx, zip и т.п. |
| **Книга-файл** | Книга, у которой ровно один файл — обычный текущий случай |
| **Книга-папка** | Книга, которая является папкой целиком. Содержимое **не интерпретируется**: внутри может быть что угодно (страницы комикса, html с ресурсами, диск с кодом) |
| **Приложение** | Не отдельная сущность. У книги-папки — это любые файлы внутри. У книги-файла — файл рядом с игнорируемым расширением, в каталог не попадает |
| **Бумажный экземпляр** | Книга без файлов. Штатное состояние, а не ошибка и не «битая запись» |
| **Серия** | Отдельного уровня нет; отложено до после MVP |
| **Архив** | Не способ хранения книги. zip/rar остаются обычными файлами, если лежат внутри книги-папки |

### Как папка становится книгой

Эвристика предлагает «эта папка — одна книга», владелец подтверждает. Решение
запоминается, чтобы при следующем сканировании не спрашивать заново.
Противоположный случай (папка с 18 PDF = 18 книг) должен распознаваться без
вопросов.

### Следствия для модели

- Сущность «роль файла» (основной текст / приложение) не нужна.
- У книги есть ровно один источник: либо файл, либо папка, либо ничего.
- Список файлов книги — это либо один файл, либо содержимое папки, прочитанное на месте.
